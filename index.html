What I do

I take a workflow that eats a person's week and turn it into a system that runs, reports on itself, and stops when it should.

Design the agent

I map the decisions inside a workflow, decide which ones a machine should own, and write down what happens when it's wrong.

Build the system

Orchestration, tool calls, retrieval and memory — wired into the software you already run, not a parallel universe beside it.

Prove it works

Repeatable tests, an answer key, and an audit trail for every action the agent takes. If I can't test it, I don't call it done.

Run the ops agent yourself

I turned the decision layer of my ops agent into a sandbox you can poke at. Adjust an incident and watch which guardrail fires — or run my 14-scenario suite and check the result against the answer key I wrote first.

It's deterministic

Rules, not a model, so the same incident always produces the same decision. That's what makes the result repeatable instead of a screenshot.

It measures itself

The page runs the suite and reports decision accuracy, how often it acted without a human, and unsafe executions — computed in your browser, not written into the HTML.

It's honest about its limits

A rules engine has no model in it. The sandbox tests the guardrail logic, not model accuracy, latency, or behaviour under real production traffic.

About me

I'm Fortune Owivri, an AI automation builder working on agentic systems: software that observes, decides and acts inside a workflow rather than waiting to be prompted. My focus is the unglamorous half of that — the guardrails, the escalation paths, and the tests that tell you whether the agent is actually doing the job.

Before this I spent five years in IT support and operations — warehouse and inventory control, field engineering, first-line support — which is where the habit comes from. It is also where the results on this page come from: the 40%, 90% and 18% figures are operations results, not agent benchmarks, and I say so on every page that mentions them.

I work mostly with n8n for orchestration, an LLM planner for judgement, vector stores for memory, and plain, understandable code wherever a rule is better than a model. I write up what I build because the write-up is where I find out whether I understood it. B.Sc. Computer Science, ESPAM Formation University (Summa Cum Laude, 4.0 GPA). Currently working toward Google Cybersecurity and CompTIA Security+.
