Log-triage lab

A small detection engine runs over an authentication log, raises alerts, and then hands you seven cases to triage. There is no server and no randomness: the same input produces the same output every time, so the numbers mean something.

The log is synthetic. It was written by hand to exercise the detection rules — it is not captured traffic from a real network, and nothing here is a production result. What is real is the code: you can run it yourself, and the page's numbers come from that run.

How the detector works

Each line of the log is parsed into a timestamp, a source address, a user, a result and an action. Six rules then run over the parsed events, and every rule that fires produces an alert carrying the line numbers that triggered it.

brute_force

Five or more failures against one account within ten minutes.

password_spray

One source failing against five or more distinct accounts — the pattern per-account lockouts never catch.

success_after_failure

A login that succeeds after three or more failures for the same account. The one that turns noise into an incident.

off_hours_sudo

Privilege escalation outside 07:00–19:00 UTC.

off_hours_account_creation

A new account created outside business hours — a common persistence step.

external_invalid_users

Repeated attempts against usernames that do not exist, from non-private addresses.

Triage drill

Seven cases from the same environment. Choose the disposition you would give each one: benign, investigate, block, or escalate. Each answer comes with the reasoning.

Reproduce it from a terminal

The same engine runs under Node, which is how it is tested:

git clone https://github.com/Fortune5560/fortune-owivri-portfolio.git
cd fortune-owivri-portfolio
node lab/triage-engine.js          # human-readable report, exit 0 on pass
node lab/triage-engine.js --json   # machine-readable report
npm test                           # engine + drill tests

The engine exits non-zero if the log has unparsed lines, if any of the six rules fails to fire, or if fewer than two critical alerts are raised — so the site's numbers cannot drift away from the code without the tests complaining.
