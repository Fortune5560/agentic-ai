Ops Agent Sandbox

This is a working, inspectable version of the triage loop behind my operations agent. Change an incident, or run my full test suite, and watch which guardrail fires and why. Everything runs in your browser — no API key, no waiting.

  • Runs offline
  • Deterministic
  • Rules-based, not an LLM
  • Open source in this repo

What this is: the decision layer I use, reduced to deterministic rules so it can be tested. What this is not: a simulated production system, and not a claim about any client's numbers. The results below are measured by running the suite, and I only call them measured because the test is repeatable by you.

3. How to read these results honestly

What is measured

Decision agreement against a fixed answer key, how often the agent acts without a human, and whether every guardrail is actually exercised by at least one scenario. Those numbers come from executing the suite.

What is not measured

Production latency, cost per incident, model accuracy, or how this performs against real traffic. A rules engine has no model in it, and nothing on this page touches a live system.

Why an answer key

Without an independent expectation you can only measure whether the code does what the code does. Writing the expected decision first is what makes the pass rate mean something.

Reproduce locally: node demo/ops-agent-engine.js for the human-readable report, or node demo/ops-agent-engine.js --json for a diffable artifact. The script exits non-zero if any scenario diverges or the engine stops being deterministic, so it can gate a change in CI.
